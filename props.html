Props

O componente <Header /> da Ana está igual em todas as páginas — mas e se ela quiser que o título da página mude ("Início", "Sobre")? É aí que entram as props: valores que o componente pai passa para o filho, como argumentos de uma função. Nesta página você vai aprender a sintaxe e a regra de ouro entre Server e Client Components.

Você vai aprender
  • Sintaxe: <Saudacao nome="Ana" /> no pai, { nome } no filho
  • Desestruturação: function Saudacao({ nome, idade })
  • Props com valor JS: aspas para texto, chaves para número/expressão: idade={20}
  • Props entre Server → Client: só valores serializáveis (texto, número, objeto, array)
  • ❌ Server não pode passar função para Client (erro real)
  • Props só descem (pai → filho); o filho não altera as props

A ideia: props são bilhetes que o pai cola na mão do filho

Imagine que a Ana (o componente pai) vai mandar o filho (o componente filho) numa tarefa: "leva esse bilhete para a padaria". O bilhete é a prop: um valor que o pai entrega para o filho usar. No código, o pai escreve <Saudacao nome="Ana" /> — como se colocasse um bilhetinho escrito nome: "Ana" na mão do componente Saudacao. Dentro do filho, a função recebe esse bilhete desempacotado: function Saudacao({ nome }) — e usa {nome} no JSX. Simples assim: o pai manda, o filho recebe e usa.

Tem uma regrinha de sintaxe importante: texto vai entre aspas (nome="Ana"), mas número, variável ou expressão vai entre chaves (idade={20}, ano={2025}, dobro={n * 2}). As chaves são a janelinha do JSX de novo — tudo que é JavaScript entra nelas.

E a regra de ouro entre Server e Client: quando um Server Component manda props para um Client Component, esses valores atravessam a "fronteira" entre servidor e navegador — eles viram JSON no meio do caminho. Então só dá para passar o que existe em JSON: string, número, booleano, null, array e objeto. Função não existe em JSON, então passar um onClick={minhaFuncao} de um Server Component para um Client Component dá erro. (Client → Client pode passar função à vontade.)

Ana e o bilhetinho na lancheira: o pai entrega, o filho só lê

Toda manhã o pai da Ana coloca um bilhetinho na lancheira dela: "hoje tem excursão, leve o casaco". A Ana (filha) só lê o bilhete — ela não pode reescrever o que o pai escreveu, porque a lancheira é dele. Uma prop é esse bilhete: o componente pai entrega um valor (nome="Ana") e o componente filho usa ({nome}) — somente leitura, como um bilhete que não se apaga.

Se o filho quiser mudar alguma coisa, ele não rasura o bilhete — ele pede para o pai (chama a função passada por prop, o famoso callback) ou guarda uma cópia no próprio bolso (estado interno). Essa é a regra de ouro das props: dados descem, eventos sobem — o que mantém os componentes da Ana previsíveis como uma lancheira bem organizada.

Exemplo completo: Saudacao

// O filho: recebe as props desempacotadas no parâmetro
export default function Saudacao({ nome, idade }) {
  return (
    <div>
      <h1>Olá, {nome}!</h1>
      <p>Você tem {idade} anos.</p>
    </div>
  );
}
import Saudacao from "../components/Saudacao";

export default function Home() {
  return (
    <main>
      <Saudacao nome="Ana" idade={20} />
      <Saudacao nome="Bruno" idade={31} />
    </main>
  );
}

Resultado na tela: Olá, Ana! Você tem 20 anos. e Olá, Bruno! Você tem 31 anos. — mesmo componente, dados diferentes. Repare: nome="Ana" (texto, com aspas) e idade={20} (número, com chaves).

Props entre Server e Client na prática

// Server Component (padrão)
import Contador from "../components/Contador"; // ← esse tem "use client"

export default function Home() {
  return (
    <main>
      <h1>Página server</h1>
      {/* props serializáveis passam tranquilo: */}
      <Contador titulo="Cliques" valorInicial={10} />
    </main>
  );
}
"use client";

import { useState } from "react";

export default function Contador({ titulo, valorInicial }) {
  const [n, setN] = useState(valorInicial);
  return <button onClick={() => setN(n + 1)}>{titulo}: {n}</button>;
}

Quando dá errado

Erro 1: o Server Component tentou passar uma função para um Client Component:
Error: Functions cannot be passed directly to Client Components unless you
explicitly expose it by marking it with "use server".
  <Contador onClique={() => ...} />

Dica do guia: de Server para Client só passam valores serializáveis
(string, número, objeto, array). Funções só entre Client → Client
(ou via Server Actions, que é assunto do Nível 2).
Erro 2: esqueceu as chaves no valor numérico e passou string:
<Saudacao idade="20" />  → idade chega como texto "20"
<Saudacao idade={20} />    → idade chega como número 20

Dica do guia: texto usa aspas, código JavaScript usa chaves.
Se precisar de conta (idade + 1), passe número: idade={20}.
