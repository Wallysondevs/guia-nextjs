Cookies e sessões básicas

A Ana 👩‍💻 queria que o visitante ficasse "logado" entre páginas sem mandar token no JavaScript. A resposta é o cookie httpOnly: um bilhete que o navegador guarda e manda de volta sozinho em cada pedido — o servidor lê com await cookies(), e só uma Server Action ou Route Handler pode escrever (cookies().set). Nesta página você monta uma sessão básica de login.

Você vai aprender
  • await cookies() e await headers() em Server Components (Next 15 é async!)
  • Ler cookie: store.get("sessao")?.value
  • Gravar/apagar cookie só em Server Action ou Route Handler
  • Opções: httpOnly, path, maxAge, secure, sameSite
  • Uma sessão básica: login grava, página protege, logout apaga

A ideia: o crachá plastificado que o segurança carimba na entrada

Em um evento, na entrada o segurança carimba um crachá plastificado (o cookie) e te entrega. A partir daí, em cada porta interna, o segurança só olha o seu crachá — você não precisa mostrar documento de novo. O navegador faz exatamente isso: guarda o cookie e manda no header Cookie: de cada requisição sozinho.

No Next.js 15, ler esse crachá no servidor é const store = await cookies(); store.get("sessao")?.value — dentro de um Server Component, Server Action ou Route Handler. É async agora (migração importante do Next 15). E gravar? Só dá para gravar ou apagar cookie dentro de uma Server Action ou Route Handler — nunca numa página renderizada, porque a resposta HTML já está sendo montada; o lugar certo é a action de login/logout.

Para sessão, o padrão ouro é httpOnly: true (o JavaScript do navegador não consegue ler o cookie — protege contra roubo por XSS) + secure: true em produção (só HTTPS) + sameSite: "lax" (protege contra CSRF básico) + maxAge em segundos. Em produção real, troque o valor por um token assinado/JWT — aqui a Ana usa um valor simples só para aprender.

Ana e o bilhete de entrada do show: provar quem você é sem mostrar o RG

Na entrada de um show, a Ana mostra o RG uma vez e recebe um bilhete plastificado no peito. Dali em diante ela só mostra o bilhete — o segurança não precisa ver o documento de novo, e o bilhete não pode ser falsificado porque tem o carimbo da casa. Um cookie de sessão é esse bilhete: o servidor assina um identificador (httpOnly, para o JavaScript do navegador não tocar) e a cada requisição o navegador devolve o bilhete provando quem é a Ana.

A sessão é o que o bilhete aponta: no servidor fica um registro "bilhete nº 123 = Ana, logada às 14h". Quando a Ana faz logout, o servidor rasga o registro — o bilhete continua no navegador, mas não vale mais nada, como um ingresso de show depois que o evento acabou.

Ler cookies e headers no servidor

import { cookies, headers } from "next/headers";
import { redirect } from "next/navigation";

export default async function Painel() {
  // Next.js 15: cookies() e headers() são assíncronos — await obrigatório
  const store = await cookies();
  const sessao = store.get("sessao")?.value;

  if (!sessao) redirect("/login"); // não logado -> manda pro login

  const h = await headers();
  const navegador = h.get("user-agent"); // dá para ler qualquer header do pedido

  return (
    <div>
      <h1>Painel da Ana 👋</h1>
      <p>Sessão: {sessao.slice(0, 8)}…</p>
      <small>Seu navegador: {navegador}</small>
    </div>
  );
}

Login e logout: gravar e apagar o cookie na action

"use server";

import { cookies } from "next/headers";
import { redirect } from "next/navigation";

export async function entrar(estadoAnterior, formData) {
  const email = formData.get("email");
  const senha = formData.get("senha");

  if (email !== "ana@exemplo.com" || senha !== "1234") {
    return { erro: "E-mail ou senha errados" };
  }

  const store = await cookies();
  store.set("sessao", "token-secreto-da-ana", {
    httpOnly: true,        // JS do navegador não lê
    secure: process.env.NODE_ENV === "production", // só HTTPS em produção
    sameSite: "lax",       // manda o cookie em navegação normal
    path: "/",             // vale no site inteiro
    maxAge: 60 * 60 * 24,  // 1 dia, em segundos
  });

  redirect("/painel");
}

export async function sair() {
  const store = await cookies();
  store.delete("sessao"); // apaga o crachá
  redirect("/login");
}

function App() {

  function fazerLogin() {}

  // 👉 apaga a sessão (equivalente a cookies().delete("sessao"))
  function fazerLogout() {}

  const logado = Boolean(cookies.sessao);

  return (
    <div style={{ fontFamily: "sans-serif", padding: 16 }}>
      <button onClick={fazerLogin}>Entrar (grava cookie)</button>
      <button onClick={fazerLogout}>Sair (apaga cookie)</button>

}
function App() {
  const [cookies, setCookies] = React.useState({});

  function fazerLogin() {
    setCookies({ ...cookies, sessao: "abc123" }); // httpOnly no servidor
  }

  function fazerLogout() {
    const copia = { ...cookies };
    delete copia.sessao;
    setCookies(copia);
  }

  const logado = Boolean(cookies.sessao);

  return (
    <div style={{ fontFamily: "sans-serif", padding: 16 }}>
      <button onClick={fazerLogin}>Entrar (grava cookie)</button>
      <button onClick={fazerLogout}>Sair (apaga cookie)</button>
      <p>{logado ? "Logado ✔ sessão: " + cookies.sessao : "Não logado"}</p>
    </div>
  );
}

Quando dá errado

Erro: tentar gravar cookie durante a renderização da página — a API nova avisa na hora:
Error: Cookies can only be modified in a Server Action or Route Handler.
Read more: https://nextjs.org/docs/messages/cookies-in-server-component
// (ou, no Next 15, o aviso de que cookies() é async:)
Error: cookies() should be awaited before using its value — `cookies` is a Promise in Next.js 15

Tradução: cookies só podem ser modificados numa Server Action ou Route Handler (numa página renderizada a resposta já está sendo escrita), e no Next 15 é preciso await cookies() antes de usar. Correção: faça o set/delete dentro da action de login/logout (como no exemplo) e sempre com await. Outro erro clássico: mandar o cookie sem path: "/" — aí ele só vale na rota atual e some na próxima página.
