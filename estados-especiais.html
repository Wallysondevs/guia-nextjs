Estados especiais: loading, error, 404

A Ana 👩‍💻 tinha uma página de post que buscava dados no banco e demorava 2 segundos. Nesses 2 segundos a tela travava em branco — dava a impressão de que o site tinha quebrado. Ela scopriu que o App Router tem três arquivos mágicos para esses momentos: loading.jsx (enquanto espera), error.jsx (quando quebra) e not-found.jsx (quando a rota não existe).

Você vai aprender
  • loading.jsx: o Suspense automático em volta da página
  • error.jsx: precisa de "use client" e recebe reset
  • not-found.jsx + notFound() para o 404
  • Hierarquia: o arquivo mais próximo da rota é o que vale

A ideia: o balcão de atendimento com senha, placa de reforma e placa de 404

Um banco tem três placas diferentes. Quando você entra e a senha ainda não chamou, aparece a placa "aguarde" — é o loading.jsx: enquanto o Server Component busca dados, o Next.js envolve a página num Suspense e mostra esse arquivo na hora, sem bloquear o resto do layout.

Se o cofre está trancado e o sistema cai, o atendente coloca a placa "deu problema, clique para tentar de novo" — é o error.jsx: qualquer erro lançado dentro da página (fetch quebrado, divisão por zero, throw seu) cai nesse arquivo, que recebe o erro e uma função reset() para tentar renderizar de novo. Ele precisa ser Client Component ("use client") porque usa o botão.

E se você procura uma agência que não existe? A placa "404 — não encontrado" — é o not-found.jsx, disparado quando a rota não casa com nada ou quando você chama notFound() no código (lembra da página de rotas dinâmicas?).

Ana e a senha da fila do banco: 'aguarde, já já atendemos'

No banco, às vezes a Ana pega uma senha e vê na tela "aguarde um instante…". Ela não sai da fila achando que deu errado — ela sabe que o atendente está chegando. O arquivo loading.jsx é essa telinha de "aguarde": enquanto a página demora (buscando dados, por exemplo), o Next mostra o loading no lugar dela. O error.jsx é o aviso de "não conseguimos atender agora, tente de novo" — com um botão de tentar outra vez (reset). E o not-found.jsx é a placa de "guichê inexistente" — o 404.

A grande vantagem para a Ana: esses três arquivos vivem na mesma pasta da rota, como três guichês do mesmo corredor. Ela não precisa escrever if (carregando) ... else if (erro) ... dentro da página — o próprio Next escolhe qual guichê mostrar, e a experiência fica uniforme no site inteiro.

Os três arquivos na prática

export default function Loading() {
  return <p>Carregando post… ⏳</p>;
}
"use client"; // obrigatório: usa o botão onClick

export default function Error({ error, reset }) {
  return (
    <div>
      <h2>Deu ruim 😵</h2>
      <p>{error.message}</p>
      <button onClick={() => reset()}>Tentar de novo</button>
    </div>
  );
}
import Link from "next/link";

export default function NotFound() {
  return (
    <div>
      <h1>404 — página não encontrada</h1>
      <p>A URL que você procurou não existe.</p>
      <Link href="/">← Voltar ao início</Link>
    </div>
  );
}

Hierarquia importante: o Next.js procura o arquivo mais próximo da rota. Se existir app/blog/[id]/error.jsx, ele cobre só os posts; se existir só app/error.jsx, cobre tudo abaixo de app. O not-found.jsx de app/ vira o 404 global; o notFound() chamado numa página usa o not-found.jsx mais próximo dela.

error.jsxqualquer erro lançado na página/segmentoprecisa de "use client"; recebe { error, reset }
not-found.jsxrota inexistente ou notFound() chamadoServer Component; status 404

template.jsxre-renderiza a cada navegação (diferente do layout)útil para animações de entrada

Missão: a Ana simulou um fetch que falha na primeira tentativa. Complete o botão para chamar tentarDeNovo() (que aumenta tentativas e tenta de novo). Dica: renderize a mensagem de erro quando falhou for verdadeiro.

function App() {
  const [tentativas, setTentativas] = React.useState(0);
  // falha nas 2 primeiras tentativas, dá certo na 3ª
  const falhou = tentativas < 2;

  function tentarDeNovo() {
    setTentativas(tentativas + 1);
  }

  return (
    <div style={{ fontFamily: "sans-serif", padding: 16 }}>
      {falhou ? (
        <div>
          <h2>Deu ruim 😵 (tentativa {tentativas + 1})</h2>
          <button>Tentar de novo</button>
        </div>
      ) : (
        <p>Carregou! 🎉</p>
      )}
    </div>
  );
}

Quando dá errado

Erro: esquecer o "use client" no error.jsx. Como o arquivo usa onClick, o build acusa na hora:
Error: Event handlers cannot be passed to Client Component props.
  <button onClick={function} className="…">
Did you forget "use client"? — app/blog/[id]/error.jsx

Tradução: não dá para passar função de evento (onClick) para um Server Component — faltou a diretiva "use client" no topo do arquivo. Correção: primeira linha de error.jsx (e de loading.jsx se ele usar estado) deve ser "use client";. Outro erro real: chamar notFound() dentro de um Client Component — não funciona; chame no servidor (página/layout) ou numa Server Action/Route Handler.
