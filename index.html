Aprenda Next.js do zero, experimentando na hora

Um guia em português, no estilo escola: cada página ensina um conceito só, explica com uma analogia do dia a dia, mostra o código linha por linha e deixa você rodar o componente dentro da própria página — sem instalar nada para começar.

A Ana já sabia JavaScript e React: variáveis, funções, componentes, props e estado com useState. Ela conseguia fazer uma lista de tarefas que se atualizava sozinha dentro de uma página. Mas quando quis publicar o projeto de verdade, apareceram perguntas novas: como o Google vai ler o conteúdo da página? Como crio rotas como /sobre e /blog/meu-post? Onde escondo a chave secreta da API para ninguém ver? Foi aí que ela scopriu o Next.js: em vez de montar cada peça do carro na mão, ela escreve componentes React e o framework entrega o carro completo — rotas, páginas que o buscador enxerga, imagens otimizadas e deploy. Este guia existe para encurtar esse caminho para você.

Você vai aprender
  • o que é o Next.js e por que ele existe (framework vs biblioteca);
  • App Router vs Pages Router — e por que o App Router é o padrão hoje;
  • a preparar o computador: Node.js, npm e o terminal;
  • a criar um projeto de verdade com create-next-app e entender cada pasta;
  • a transformar pastas com page.tsx em rotas do site;
  • a rodar o app local com npm run dev e usar o hot reload;
  • a usar a caixa Experimente desta página para treinar sem medo;
  • e, depois, layouts, <Link>, Server vs Client Components, rotas dinâmicas, data fetching e Server Actions.

A ideia: React é o motor, Next.js é o carro completo

Imagine que o React puro é como um motor de carro: potente, mas sozinho não anda — precisa de rodas, volante, carroceria e papelada. O Next.js pega esse motor e monta o carro inteiro ao redor dele. Você continua escrevendo componentes React do jeito que já conhece, mas o framework cuida das rotas, das páginas que o Google consegue ler (renderização no servidor), das imagens que carregam rápido, das fontes e até da publicação na Vercel. Resultado: um site rápido, bem posicionado no buscador e fácil de manter.

O coração do Next.js atual é o App Router: em vez de uma pasta pages/ em que cada arquivo vira uma rota, você cria a pasta app/ e, dentro dela, cada subpasta que contém um arquivo page.tsx vira uma página — app/sobre/page.tsx vira /sobre. E um arquivo layout.tsx numa pasta envolve todas as páginas abaixo dela com o mesmo cabeçalho e rodapé, como um molde de biscoito reutilizável. Esse é o "roteamento por arquivos" (file-based routing): a estrutura de pastas é o mapa do seu site.

Experimente agora mesmo

Toda caixa Experimente deste guia é um mini editor de código React vivo: o código fica dentro de uma caixa editável e, ao clicar em ▶ Rodar, o navegador compila o JSX na hora (com o Babel) e renderiza o componente com o React 19 dentro de um quadradinho logo abaixo — o mesmo React que o Next.js usa por dentro das páginas dele. Você pode editar à vontade: se estragar, é só clicar em ↺ Restaurar. O botão ✔ Verificar missão confere se o seu código bate com o objetivo.

Missão: mude o texto do botão de "Clique em mim" para "Somar +1". Depois clique em ▶ Rodar e em ✔ Verificar missão.

function App() {
  // useState cria uma "caixinha de memória" dentro do componente:
  // cliques começa em 0 e setCliques é a função que muda o valor dela.
  const [cliques, setCliques] = React.useState(0);

  return (
    <div style={{ textAlign: "center", padding: 24, fontFamily: "sans-serif" }}>
      <h1>Olá! Eu sou um componente React.</h1>
      <p>Você clicou {cliques} vezes.</p>
      {/* onClick recebe a FUNÇÃO, não a chamada: setCliques(cliques + 1) */}
      <button onClick={() => setCliques(cliques + 1)}>
        Clique em mim
      </button>
    </div>
  );
}

Como cada página deste guia funciona

Todas as páginas seguem o mesmo roteiro, para o seu cérebro não precisar reaprender a ler a cada aula:

  1. A ideia primeiro — uma analogia longa do mundo real (motor de carro, molde de biscoito, fichário) antes de qualquer código;
  2. Você vai aprender — um resumo em caixa amarela do que sai daquela página;
  3. O código — em blocos escuros com o nome do arquivo (page.tsx, layout.tsx…), comentado linha por linha quando é código novo;
  4. Experimente — a caixa editável com missão e gabarito;
  5. Quando dá errado — um erro comum cometido de propósito, com a mensagem real que aparece;
  6. Exercícios — perguntas de múltipla escolha que conferem na hora e um "complete o código".

Quando dá errado

Errar faz parte: o editor da caixa Experimente mostra o erro em português, embaixo do código. O erro mais comum de quem está começando em JSX é esquecer de fechar uma tag. A Ana vez ou outra esquecia o </h1> e o componente simplesmente não aparecia:

Erro comum: tag JSX aberta sem fechar. O navegador não mostra nada na tela — em vez disso, a caixa de erro aparece com a mensagem do compilador.
export default function Pagina() {
  return (
    <div>
      <h1>Olá, mundo!
      <p>Esqueci de fechar o h1 acima...</p>
    </div>
  );
}
⚠ SyntaxError: page.tsx: Expected corresponding JSX closing tag for <h1>.
   Toda tag aberta precisa de uma tag fechando: escreva </h1> depois do texto.
