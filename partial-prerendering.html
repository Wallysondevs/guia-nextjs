Partial Prerendering (PPR): estático e dinâmico na mesma página

A Ana queria o melhor dos dois mundos numa página só: a capa e o menu estáticos (rápidos, cacheáveis) e o preço do produto ao vivo (dinâmico). Com o PPR — Partial Prerendering, ainda experimental — o Next.js entrega exatamente isso: um "shell" estático servido na hora e ilhas dinâmicas que chegam por streaming dentro do mesmo HTML.

Você vai aprender
  • O que é PPR: um único HTML com parte pré-renderizada (estática) + <Suspense> para o resto
  • Ativar com experimental: { ppr: true } (Next.js 15: ppr: 'incremental' + dynamicIO) no next.config
  • O que pode ficar fora do Suspense (estático) e o que precisa ficar dentro (dinâmico)
  • O custo: a página shell é servida do cache e a parte dinâmica é "furada" depois

A ideia: a capa da revista com o preço riscado a caneta

Imagine uma revista impressa: a capa, o índice e os artigos são todos iguais para todo mundo — foram impressos uma vez e ficam prontos na banca (isso é o shell estático). Só um pedacinho, o preço riscado à mão na hora, muda para cada cliente (isso é a parte dinâmica). O PPR é essa revista: o Next.js pré-renderiza tudo que é igual para todos e deixa "buracos" com <Suspense> exatamente onde os dados precisam ser frescos — cookies(), headers(), banco de dados ao vivo.

Na prática, a primeira requisição recebe o shell estático instantâneo (vem do cache/CDN) com os fallbacks nos buracos, e o servidor continua o trabalho em segundo plano: quando a parte dinâmica fica pronta, ela entra no lugar via streaming — a mesma mágica da aula anterior, mas agora metade da página já está cacheada. O resultado: TTFB baixo (rápido) e dados frescos onde precisa.

A regra prática da Ana: tudo que não depende do pedido pode ficar fora do Suspense (nome do site, layout, lista de categorias cacheada) e vira parte do shell estático; tudo que lê o pedido (cookies(), params de busca, dados que mudam toda hora) entra num <Suspense> e vira ilha dinâmica.

Ana imprime a capa da revista de manhã, mas a cotação entra ao vivo

A revista da banca sai com a capa impressa de madrugada — fotos, manchetes, índice, tudo estático. Só a cotação do dólar, aquela caixinha no canto, é atualizada ao vivo por um telão. O Partial Prerendering (PPR) é essa revista: a parte estática da página é gerada no build (a capa), e só os trechos marcados como dinâmicos (o telão) são renderizados na hora da requisição, dentro de um <Suspense>.

A Ana não precisa escolher entre "página 100% estática" e "página 100% dinâmica": com o PPR ela tem as duas na mesma página. É a capa impressa (rápida, cacheável, barata de servir) com a caixinha ao vivo (dados frescos do banco) — o melhor dos dois mundos numa única rota.

Ativando o PPR e separando as partes

/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    ppr: 'incremental', // Next.js 15: PPR incremental (antes era true/false)
  },
};

module.exports = nextConfig;
import { Suspense } from 'react';
import Header from './Header';        // estático: fora do Suspense -> vira parte do shell
import PrecoAoVivo from './PrecoAoVivo'; // dinâmico: dentro do Suspense -> ilha

export const experimental_ppr = true; // opt-in por rota (modo incremental)

export default function Home() {
  return (
    <>
      <Header />  {/* shell estático: servido do cache na hora */}
      <main>
        <h1>🛒 Loja da Ana</h1>
        <p>Produtos e descrição: estáticos.</p>
        <Suspense fallback={<p>⏳ Buscando preço atual…</p>}>
          <PrecoAoVivo />  {/* ilha dinâmica: completa depois, via streaming */}
        </Suspense>
      </main>
    </>
  );
}
import { cookies } from 'next/headers';

export default async function PrecoAoVivo() {
  // qualquer leitura de pedido (cookies/headers) ou fetch no-store => island dinâmica
  const session = await cookies();
  const res = await fetch('https://api.exemplo.com/preco', { cache: 'no-store' });
  const { preco } = await res.json();
  return <p>💵 Preço agora (para a sua sessão): <strong>R$ {preco}</strong></p>;
}

Missão: no código abaixo, o <Header /> está dentro do Suspense junto com o preço — assim ele também fica esperando. Mova o <Header /> para fora do <React.Suspense> e deixe só o <Preco /> dentro, com um fallback de "carregando preço…". Rode antes e depois para sentir a diferença. Depois clique em Verificar missão.

function Header() {
  return <p>🏠 Loja da Ana — shell que poderia ser estático</p>;
}

function Preco() {
  // simula dado ao vivo (2s)
  const P = React.lazy(() => new Promise(res => setTimeout(() =>
    res({ default: () => <p>💵 Preço ao vivo: R$ 99,90</p> }), 2000)));
  return <P />;
}

function App() {
  return (
    <div>
      {/* TODO: tire o Header daqui de dentro e coloque antes do Suspense */}
      <React.Suspense fallback={<p>⏳ carregando…</p>}>
        <Header />
        <Preco />
      </React.Suspense>
    </div>
  );
}

Quando dá errado

Erro real: ativar PPR sem o modo incremental e usar leitura dinâmica fora do Suspense. O build falha dizendo que a rota usa IO dinâmico sem estar coberta por Suspense:
Error: Route / used dynamic IO (cookies/headers/fetch no-store) outside a Suspense
boundary with PPR enabled. Wrap the dynamic part in <Suspense> or disable PPR
for this route with `export const experimental_ppr = false`.
Confusão comum: a página "não atualizou" depois de ligar o PPR. Com PPR incremental, só as rotas com export const experimental_ppr = true participent — as outras continuam no comportamento antigo. E lembre: a parte estática só é recriada no deploy ou no revalidate; a parte dinâmica é que é ao vivo.
GET /  →  served from cache (shell estático, ~30ms)
   ↳ Suspense island: preço ao vivo completado em 400ms (streaming)
