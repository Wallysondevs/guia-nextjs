Grupos de rotas (grupo)

A Ana 👩‍💻 estava montando um site com duas "áreas": a loja (home, produto, carrinho) e o marketing (sobre, contato). Ela queria um layout diferente para cada área — cabeçalho de loja num lado, institucional do outro — mas não queria que a URL ficasse /loja/produto/1. A solução foram as pastas entre parênteses: (shop) e (marketing).

Você vai aprender
  • Por que (nome) organiza o projeto sem virar URL
  • Dar um layout.jsx exclusivo para um grupo de rotas
  • Ter vários layouts raiz (um por grupo) no mesmo app
  • Nomear rotas iguais em grupos diferentes sem conflito

A ideia: pastas com nome de sala, não de endereço

Imagine um prédio comercial: no térreo há duas recepções — uma da loja, uma do coworking. Cada recepcionista (cada layout.jsx) atende só quem entra pela porta dela, mas o endereço do prédio não muda: não existe rua chamada "recepção-da-loja". A pasta (shop) funciona assim: ela existe no disco, organiza os arquivos e carrega o layout do grupo, mas o texto entre parênteses nunca aparece na URL.

É por isso que dá para ter app/(shop)/page.jsx e app/(marketing)/page.jsx ao mesmo tempo: ambas respondem por /? Não — dá conflito, e o Next.js avisa. O truque é que dentro de cada grupo você pode repetir nomes de rota livremente: (shop)/produto/[id]/page.jsx vira /produto/1, e (marketing)/produto/page.jsx (uma página "sobre o produto") também poderia existir sem bater boca, porque os caminhos completos são diferentes.

E o layout? Cada grupo pode ter o seu próprio layout.jsx, que envolve só as páginas daquele grupo — o layout raiz app/layout.jsx continua envolvendo tudo por fora. Resultado: a loja usa cabeçalho de loja, o marketing usa cabeçalho institucional, e a URL continua limpa.

Ana organiza os andares do prédio: (marketing) e (loja) no mesmo endereço

Num prédio comercial, a Ana pode ter a loja no térreo (meusite.com.br/) e o marketing no segundo andar (meusite.com.br/sobre) — o endereço é o mesmo, mas os andares são separados, cada um com a sua recepção. No Next.js, a pasta entre parênteses — (grupo) — faz exatamente isso: ela organiza sem entrar na URL. app/(loja)/page.jsx vira /, e app/(marketing)/sobre/page.jsx vira /sobre, e cada grupo pode ter o seu próprio layout.jsx.

É como ter duas recepções no mesmo prédio: o visitante não vê "(marketing)" no endereço, mas cada área tem a sua cara. A Ana usa grupo quando quer layouts diferentes (loja com vitrine, blog com sidebar) sem sujar a URL com prefixos.

Na prática: loja + marketing no mesmo app

app/
├─ layout.jsx                  ← layout raiz (html, body, fonte…)
├─ (shop)/                     ← grupo: NÃO vira URL
│   ├─ layout.jsx              ← layout só da loja (header 🛒)
│   ├─ page.jsx                →  /            (home da loja)
│   ├─ produto/[id]/page.jsx   →  /produto/1
│   └─ carrinho/page.jsx       →  /carrinho
└─ (marketing)/                ← outro grupo
    ├─ layout.jsx              ← layout institucional
    └─ sobre/page.jsx          →  /sobre
export default function ShopLayout({ children }) {
  return (
    <div>
      <header>🛒 Minha Loja — frete grátis acima de R$ 99</header>
      <main>{children}</main>
      <footer>© Loja da Ana</footer>
    </div>
  );
}
export default function MarketingLayout({ children }) {
  return (
    <div>
      <header>🏠 Sobre nós</header>
      <main>{children}</main>
    </div>
  );
}

Repare que (shop)/page.jsx responde à URL /: o grupo some do caminho. Se duas rotas finais iguais existirem em grupos diferentes (ex: (a)/sobre/page.jsx e (b)/sobre/page.jsx), aí sim o Next.js reclama no build com erro de rota duplicada — nesse caso é só dar nomes diferentes ou mover uma para fora do grupo.

Missão: a Ana separou as abas em dois "grupos" (loja 🛒 e marketing 🏠). Complete a função rotasDoGrupo para devolver só as rotas daquele grupo, comparando rota.grupo com o grupo recebido. Rode com os dois botões.

function App() {
  const rotas = [
    { caminho: "/", grupo: "shop", nome: "Home da loja" },
    { caminho: "/carrinho", grupo: "shop", nome: "Carrinho" },
    { caminho: "/sobre", grupo: "marketing", nome: "Sobre nós" },
  ];
  const [grupo, setGrupo] = React.useState("shop");

  // 👉 devolva só as rotas cujo grupo bate com `grupo`
  const rotasDoGrupo = [];

  return (
    <div style={{ fontFamily: "sans-serif", padding: 16 }}>
      <button onClick={() => setGrupo("shop")}>🛒 loja</button>
      <button onClick={() => setGrupo("marketing")}>🏠 marketing</button>
      <ul>
        {rotasDoGrupo.map((r) => (
          <li key={r.caminho}>{r.caminho} — {r.nome}</li>
        ))}
      </ul>
    </div>
  );
}
function App() {
  const rotas = [
    { caminho: "/", grupo: "shop", nome: "Home da loja" },
    { caminho: "/carrinho", grupo: "shop", nome: "Carrinho" },
    { caminho: "/sobre", grupo: "marketing", nome: "Sobre nós" },
  ];
  const [grupo, setGrupo] = React.useState("shop");

  const rotasDoGrupo = rotas.filter((r) => r.grupo === grupo);

  return (
    <div style={{ fontFamily: "sans-serif", padding: 16 }}>
      <button onClick={() => setGrupo("shop")}>🛒 loja</button>
      <button onClick={() => setGrupo("marketing")}>🏠 marketing</button>
      <ul>
        {rotasDoGrupo.map((r) => (
          <li key={r.caminho}>{r.caminho} — {r.nome}</li>
        ))}
      </ul>
    </div>
  );
}

Quando dá errado

Erro: criar duas rotas finais iguais em grupos diferentes. É o erro mais comum de grupo:
Error: You cannot use different slug names for the same dynamic path ("id" !== "slug").
// ou, no caso de grupos:
Error: You cannot have two parallel pages that resolve to the same path! /page — (a)/page.jsx and (b)/page.jsx

Tradução: duas páginas paralelas resolvem para o mesmo caminho. Correção: renomeie uma das rotas ou tire uma delas do grupo. Se a ideia era realmente duas páginas "iguais" para públicos diferentes, o caminho certo é uma rota dinâmica (/[lang]/page.jsx) ou conteúdo condicional — não dois grupos com a mesma rota final.
