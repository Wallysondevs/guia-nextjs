Formulário completo com Server Action

A Ana 👩‍💻 fez a página de contato dela: nome, e-mail e mensagem. Ela queria que, ao enviar vazio, cada campo mostrasse o erro ao lado dele, sem perder o que já foi digitado, e que o botão virasse "Enviando…" enquanto a action rodava no servidor. Nesta página você monta esse formulário inteiro, do zero ao deploy mental.

Você vai aprender
  • Separar a action em arquivo próprio (actions.js) e a validação dentro dela
  • Devolver um objeto de erros por campo: { erros: { nome: "…" } }
  • useActionState ligando o formulário à action
  • Manter os valores digitados com defaultValue + estado
  • useFormStatus no botão filho + revalidatePath no fim

A ideia: o check-in de aeroporto com bilete de erro por campo

No check-in de aeroporto, o atendente confere cada documento na hora: passaporte? bagagem? passagem? Se falta alguma coisa, ele devolve aquele item específico com uma etiqueta de erro — você não perde os outros documentos, só corrige o que falta. A Server Action de formulário funciona igual: ela valida campo por campo no servidor e devolve um objeto erros com uma chave por campo. O cliente não revalida nada — a lógica pesada fica no servidor, onde mora o banco.

E por que o que você digitou não some? Porque o formulário é reenviado pelo navegador com os valores, e você reaplica com defaultValue vindo do estado. Já o botão "Enviando…" é pura leitura: o useFormStatus, num componente filho do <form>, enxerga o pending do envio e troca o texto do botão sozinho.

Fluxo completo: submit → navegador faz POST para a action → action valida → devolve { ok, erros } → useActionState guarda isso no state → a página re-renderiza mostrando os erros ao lado dos campos → se deu certo, a action chama revalidatePath e redirect.

Ana e o totem de pedido do fast-food: você preenche, a cozinha recebe direto

No fast-food novo, a Ana preenche o pedido num totem e o pedido vai direto para a cozinha — ela não leva um papel até o balcão. Uma Server Action é esse totem: o formulário da página chama uma função que roda no servidor, como se a Ana levasse o pedido até a cozinha sem sair do lugar. O navegador não processa nada além de enviar — e a página pode atualizar sozinha depois, sem reload.

A validação acontece do lado de verdade: se o e-mail da Ana ficou sem @, a action devolve o erro e o formulário mostra a mensagem na hora. É o totem dizendo "e-mail inválido" na hora, em vez de a Ana descobrir em casa que o pedido não chegou.

A action com validação (lado do servidor)

"use server";

import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";

export async function enviarMensagem(estadoAnterior, formData) {
  const nome = String(formData.get("nome") || "").trim();
  const email = String(formData.get("email") || "").trim();
  const mensagem = String(formData.get("mensagem") || "").trim();

  // validação no servidor — o cliente não manda regra nenhuma
  const erros = {};
  if (nome.length < 3) erros.nome = "Nome precisa de 3+ letras";
  if (!/^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(email)) erros.email = "E-mail inválido";
  if (mensagem.length < 10) erros.mensagem = "Mensagem muito curta (mín. 10)";

  if (Object.keys(erros).length > 0) {
    return { ok: false, erros, valores: { nome, email, mensagem } };
  }

  await db.mensagem.create({ nome, email, mensagem });
  revalidatePath("/contato");
  redirect("/contato?enviado=1"); // ou retorne { ok: true } e deixe na página
}

O formulário no cliente

"use client";

import { useActionState } from "react";
import { useFormStatus } from "react-dom";
import { enviarMensagem } from "./actions";

function BotaoEnviar() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending}>
      {pending ? "Enviando… ⏳" : "Enviar mensagem"}
    </button>
  );
}

export default function ContatoForm() {
  const [state, formAction] = useActionState(enviarMensagem, {
    ok: false, erros: {}, valores: { nome: "", email: "", mensagem: "" },
  });

  return (
    <form action={formAction}>
      <div>
        <input name="nome" placeholder="Seu nome"
               defaultValue={state.valores.nome} />
        {state.erros.nome && <small>{state.erros.nome}</small>}
      </div>
      <div>
        <input name="email" placeholder="seu@email.com"
               defaultValue={state.valores.email} />
        {state.erros.email && <small>{state.erros.email}</small>}
      </div>
      <div>
        <textarea name="mensagem" placeholder="Sua mensagem…"
                  defaultValue={state.valores.mensagem} />
        {state.erros.mensagem && <small>{state.erros.mensagem}</small>}
      </div>
      <BotaoEnviar />
      {state.ok && <p>Mensagem enviada! 🎉</p>}
    </form>
  );
}

Pontos finos: o defaultValue (não value) deixa o input editável e repõe o que a pessoa digitou quando a action devolve valores; o BotaoEnviar precisa ser filho do form para o useFormStatus funcionar; e a action recebe dois argumentos por causa do useActionState: o estado anterior e o formData.

Missão: simule a validação do servidor no navegador: a função validar deve devolver um objeto erros vazio quando o nome tem 3+ letras, ou { nome: "Nome precisa de 3+ letras" } quando não tem. Escreva no campo e rode.

function App() {
  const [nome, setNome] = React.useState("");
  const [erros, setErros] = React.useState({});

  // 👉 validação "no servidor": devolve { nome: "…" } se curto demais
  function validar() {
    setErros({});
  }

  return (
    <div style={{ fontFamily: "sans-serif", padding: 16 }}>
      <input
        placeholder="Seu nome"
        value={nome}
        onChange={(e) => setNome(e.target.value)}
      />
      <button onClick={validar}>Validar</button>
      {erros.nome && <small style={{ color: "red" }}>{erros.nome}</small>}
      {!erros.nome && nome && <p>Nome ok ✔</p>}
    </div>
  );
}
function App() {

}

Quando dá errado

Erro: usar useFormStatus no mesmo componente do <form> — ele não enxerga o próprio form:
Error: useFormStatus must be used inside a component rendered within a <form>.
// pending fica sempre false e o botão nunca muda para "Enviando…"

Tradução: o useFormStatus precisa estar num componente filho do formulário. Correção: extraia o botão para um componente separado (como o BotaoEnviar acima) e renderize ele dentro do <form>. Outro erro comum: usar value no input controlado sem onChange, ou esquecer que a action do useActionState recebe o estado anterior como 1º argumento — se você declarar async function enviar(formData) e ligar no useActionState, o formData vira o estado anterior e dá formData.get is not a function.
