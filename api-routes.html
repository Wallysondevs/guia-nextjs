API Routes: app/api/…/route.js

A Ana 👩‍💻 precisava de um endpoint para o app de celular dela consumir os posts: GET /api/posts devolvia a lista, POST /api/posts criava um post novo. Em vez de subir um servidor separado, ela criou a API dentro do próprio projeto Next.js, na pasta app/api/, usando Route Handlers.

Você vai aprender
  • Criar app/api/posts/route.js com GET, POST, etc.
  • Ler query string e body com NextRequest
  • Devolver JSON e status com NextResponse.json(dados, { status })
  • Rotas dinâmicas na API: app/api/posts/[id]/route.js
  • Quando usar API Route vs. Server Action

A ideia: a portaria do prédio que também atende interfone

O seu site Next.js já tem uma "portaria" — o servidor que responde às páginas. Uma API Route é simplesmente outra mesa nessa mesma portaria: em vez de devolver HTML, devolve JSON. O endereço /api/posts não é uma página, é um arquivo route.js que exporta funções nomeadas pelo método HTTP — GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS.

Cada função recebe um NextRequest (o pedido, com URL, headers, cookies, body) e devolve um Response — e o Next.js já traz o primo turbinado, o NextResponse, com atalhos como NextResponse.json(), NextResponse.redirect() e acesso fácil a cookies. O contexto é o segundo argumento, que traz params nas rotas dinâmicas (também com await no Next 15).

E quando usar API Route em vez de Server Action? Regra prática da Ana: Server Action é para formulários e mutações da própria página (ela já revalida o cache e redireciona sozinho); API Route é para ser consumida por fora — app mobile, outro site, um curl no terminal, um webhook.

Ana e a portaria dos fundos: por que o site precisa de uma porta só para programas

Até agora a Ana só pensou na porta da frente do site — as páginas que o navegador abre. Mas imagine um prédio de apartamentos: além da portaria visível, existe a portaria dos fundos, por onde entram a encomenda, o gás e a internet. Ninguém vê essa porta, mas sem ela o prédio não funciona. Uma API Route (app/api/…/route.js) é exatamente isso: uma porta dos fundos que não devolve HTML, devolve dados puros (JSON) para outros programas — o app de celular da loja, um script de importação, o próprio navegador fazendo fetch.

A analogia ajuda a lembrar a regra de ouro: na porta da frente você pensa em visual; na porta dos fundos, em dados. Por isso a route exporta funções como GET, POST, DELETE no lugar de um componente — cada uma é um verbo HTTP atendido ali mesmo, no servidor, perto do banco de dados e das chaves secretas.

Um CRUD de posts em dois arquivos

import { NextResponse } from "next/server";

// GET /api/posts?q=next  -> lista (com filtro opcional)
export async function GET(request) {
  const { searchParams } = new URL(request.url);
  const q = searchParams.get("q") || "";
  const posts = await buscarPosts(q); // filtra no banco
  return NextResponse.json({ posts });
}

// POST /api/posts  body: { titulo, conteudo }
export async function POST(request) {
  const body = await request.json();
  if (!body.titulo) {
    return NextResponse.json(
      { erro: "campo 'titulo' é obrigatório" },
      { status: 400 }
    );
  }
  const post = await criarPost(body);
  return NextResponse.json(post, { status: 201 });
}
import { NextResponse } from "next/server";

// GET /api/posts/42 -> um post só (ou 404)
export async function GET(request, { params }) {
  const { id } = await params;
  const post = await buscarPost(id);
  if (!post) {
    return NextResponse.json({ erro: "não achei" }, { status: 404 });
  }
  return NextResponse.json(post);
}

// DELETE /api/posts/42 -> apaga
export async function DELETE(request, { params }) {
  const { id } = await params;
  await apagarPost(id);
  return new Response(null, { status: 204 }); // 204 = sem conteúdo
}

Missão: simule uma mini API no navegador: a função responder(pedido) deve devolver { status: 404, body: { erro: "não achei" } } quando o id não existe na lista, e { status: 200, body: post } quando existe. Rode com os dois botões.

function App() {
  const posts = [{ id: "1", titulo: "Só existe o post 1" }];
  const [id, setId] = React.useState("1");
  const [resposta, setResposta] = React.useState(null);

  // 👉 simule o Route Handler GET /api/posts/[id]
  function responder() {
    const achei = null;
    setResposta({ status: 0, body: {} });
  }

  return (
    <div style={{ fontFamily: "monospace", padding: 16 }}>
      <button onClick={() => { setId("1"); setResposta(null); }}>pedir id=1</button>
      <button onClick={() => { setId("99"); setResposta(null); }}>pedir id=99</button>
      <button onClick={responder}>GET /api/posts/{id}</button>
      {resposta && (
        <p>HTTP {resposta.status} — {JSON.stringify(resposta.body)}</p>
      )}
    </div>
  );
}
function App() {
  const posts = [{ id: "1", titulo: "Só existe o post 1" }];
  const [id, setId] = React.useState("1");
  const [resposta, setResposta] = React.useState(null);

  function responder() {
    const achei = posts.find((p) => p.id === id);
    if (!achei) setResposta({ status: 404, body: { erro: "não achei" } });
    else setResposta({ status: 200, body: achei });
  }

  return (
    <div style={{ fontFamily: "monospace", padding: 16 }}>
      <button onClick={() => { setId("1"); setResposta(null); }}>pedir id=1</button>
      <button onClick={() => { setId("99"); setResposta(null); }}>pedir id=99</button>
      <button onClick={responder}>GET /api/posts/{id}</button>
      {resposta && (
        <p>HTTP {resposta.status} — {JSON.stringify(resposta.body)}</p>
      )}
    </div>
  );
}

Quando dá errado

Erro: devolver o body sem await, ou esquecer que request.json() é assíncrono — o classic de API Route:
TypeError: body used already / Cannot read properties of undefined (reading 'titulo')
  at POST (app/api/posts/route.js:10:5)

Tradução: a função leu o body antes da hora (ou o body veio vazio porque o Content-Type não era application/json). Correção: sempre const body = await request.json(); e, se for um teste com curl, mandar o header -H "Content-Type: application/json". Outro erro real: nomear o arquivo app/api/posts/index.js — no App Router o arquivo obrigatoriamente se chama route.js.
